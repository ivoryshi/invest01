# 运维与发布

当前是本机单用户服务，不是公网产品。默认http://127.0.0.1:4311，PORT可指定，Ctrl+C停止；没有认证，禁止用反向代理直接公开。服务代码更新后重启；不要停止来源不明的其他进程。

## 常见问题

| 现象 | 核查与处理 |
|---|---|
| 页面无法打开 | 终端重启会关闭原服务；重新npm start，核对实际启动URL与端口 |
| 端口占用 | 换PORT，不盲目终止用户其他服务 |
| 页面仍是旧版 | 重启后端、刷新页面；检查health版本与HTML缓存版本，不只看浏览器旧页 |
| Python导入失败 | 启动前激活正确环境，检查python3与requirements版本 |
| 基金查询60秒超时、文件dataless | 数据库可能是系统云盘占位文件，先确认完整保留本机，再复查；本轮首次只读打开519秒。不要放宽回测超时或换数据掩盖I/O问题 |
| 源文件缺失/422 | 查询assets/profile，按数据说明提供授权源；不要补零价/伪造曲线 |
| 旧导出503 data_source_unavailable | 缺旧数据的面板单独显示不可用，其余面板继续加载；补授权数据后刷新，不把缺失当零收益 |
| 500 request_failed | 未预期读取/解析异常，响应不泄露路径或堆栈；停止该操作并核查数据，不自动重试写入 |
| frozen_fund_history_requires_sqlite_deserialize | 检查Python/SQLite能力，升级环境需自行确认；不可换活动库冒充原冻结版本 |
| 409版本变化 | 重新读取源版本并确认配置；冻结损坏应核验，不换current冒充原版本 |
| 导入完成但返回2 | 查看rejected/完整import_errors；失败源保留旧版本，不是全库已更新 |
| 备份报锁/运行中 | 确认正在导入或中断状态，不能忽略风险自动删除锁/改审计表 |
| 备份/恢复目标问题 | 检查真实目录、磁盘和现有文件；restore只接受新文件 |

[数据维护说明](FACTOR-DATA.md)提供CSV导入、备份/核验/恢复命令。先检查整库空间，备份包也有隐私；没有自动调度、外部加密备份或灾备保证。运行JSON不是事务系统，避免并发写入与集成测试/真实实验同时进行。

## 源码发布

远端 [ivoryshi/invest01](https://github.com/ivoryshi/invest01)，发布分支release/factor-migration-v1；历史已核验到v0.5.3，本批v0.5.6含此前尚未发布的v0.5.4/v0.5.5增量及10月6日专用编辑修复。新标签不移动旧标签，最终远端提交与回执见[发布基线](records/FACTOR-RELEASE-V056.md)和[每日记录](records/DAILY.md)。本机旧main含生成研究缓存祖先，保留本地，不merge到发布分支，不上传旧历史，不强推。

发布前：

1. 核对任务/批准、独立审查结论和迁移剩余项。
2. 运行check、portable、完整测试（有数据）、build、观察台专项与差异检查。
3. 审核git status/diff及追踪文件：仅源码、测试、文档；var只允许.gitkeep，不能含SQLite/数据/冻结/备份/实验状态/秘密。
4. 更新包、health、页面缓存/可见版本和当前README/Wiki，保留旧批次记录。
5. 创建解释性功能提交，再创建不可变v0.5.6标签，推送既有release分支及明确指定的版本标签；核对远端分支SHA与标签解析后的提交均等于功能提交，而非根据“commit成功”宣称上传。旧v0.5.4/v0.5.5若补发布须保留原提交，禁止移动已有标签。
6. 推送成功后再补发布回执文档提交，只推进分支，不移动功能标签；再次核对最终远端分支SHA。任何一步未完成均保留待发布。

网络/代理失败应登记阻碍；不修改全局代理或强推。文件云同步可能导致Git对象读取超时，可用明确的同树干净本地发布镜像，但必须验证树与原提交身份一致，不复制用户运行文件。不能以镜像新提交冒充原仓库同一SHA。

## 回滚与恢复

代码回滚以明确提交为边界，优先新反向提交；不破坏用户未提交工作，不删除var数据库/配置/归档。发布不等于生产部署，当前没有上线环境、自动回滚或认证验收。

数据库restore只是生成经核验的新文件，不自动换活动库；正式换库需停止服务/导入，验证数据口径及典型回测并单独批准，保留原库。配置/结果JSON和冻档也需自己的备份策略，整库净值备份不覆盖它们。

# 架构基线

延续已讨论的模块化 API、研究任务执行器、Python 因子执行器、PostgreSQL 和对象存储方向。它们是目标架构，尚未安装或实现；新项目的具体工程依赖与落地顺序在 N01 确认。

目录预留：apps/web 页面、apps/api 接口、workers/research 研究任务、workers/factors 因子任务、packages/contracts 公共契约、adapters 数据服务适配、tests 验证、docs/wiki 文档、var 本地运行产物。

数据接入需登记供应商、工具权限、指标定义、频率、来源时点与取数时间。缺失数据不填零；演示数据必须显式标记。TradingView、Longbridge 等能力逐项核验，不将工具可见视为数据权限可用。

每日摘要以规范化报告数据为渲染来源，保留修订版本。宏观到公司证据与反证需能回溯；因子实验保留数据、股票池、口径和引擎版本。

旧项目当前仅作参考，未复制代码，也未迁移历史数据。未来引入模块须登记原始路径、提交或文件哈希、复制时间、目标路径、适配修改及检查结果。

## N01 实施决策

先采用 Node 原生 HTTP 和静态 ES Module 页面验证独立运行与接口边界，无第三方依赖。相较立即引入完整前后端框架，此阶段便于建立可复现启动和测试基线；复杂组件、认证和持久化到对应批次确定，不以本骨架替代最终技术架构。API 仅公开明确列出的资产，固定本机监听，不提供数据库或外部 MCP 调用。

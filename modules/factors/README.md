## 实际敏感度与代理风险模型

- 行业/自建行业按同一捕获数据、区间和规则实际重跑零成本、双交易费、TopN减一/加一（不越过合法边界）、信号滞后加一；自建多输出另有首输出权重减10%。保存案例指标、参数变化、公式变体SHA及相对基线终值差，不修改入库定义/主策略。单案例行情错误单独标记unavailable，不中断有效主回测，不补造收益。
- 代理为已选因子族或正权重子节点单独生成的同规则净策略，减同日毛基准。以净策略日超额为y、市场收益和代理超额为X，带截距OLS、rf=0，列中心化标准化后求解并还原系数。至少20观测且至少两倍参数数，常数列、秩不足或条件数超过1e6拒绝独立系数。代理失败不默默用部分列；自建超过8个正输出保留主回测，但明确不计算完整代理模型。
- `riskModel`单独保存原代理逐日收益、系数、样本截距/残差、终值链接贡献、年化跟踪方差和有符号协方差贡献及闭合误差。方差=`244*Var(y,ddof=1)`；贡献=`244*Cov(component,y,ddof=1)`，负数可代表抵消；截距常数无方差贡献。代理键加`proxy:`命名空间，防止与保留模型键碰撞。
- 代理由同一行业面板/策略规则生成，有内生性；回归是事后样本内诊断，不是独立可投资因子收益、官方Smart Beta、因果Alpha或样本外证明。旧`alphaReturn/smartBetaReturn`仍为null，不用残差掩盖错误。结果口径和完整源码/数据SHA保留；历史结果不自动改写。
- 单次执行复用日历/报价索引与同参数评分缓存，诊断不保留重复评分审计或重复计算归因；同一单输出复用主账本。当前/冻结结果严格比较，未以放宽精度解决差异。

## 定投与三档现金流归因

仅用于新执行结果，旧结果不改写。复用dca_engine.py的`cashflow_attribution`，三个执行器分别记录真实期初持仓与现金、市场损益、收盘投入、显式年费与交易/申购费、基准毛收益及基准费用。结果保留完整逐日输入/贡献、月度金额、资金/终值核对和计算口径；详情新增功能性归因表，未调整CSS或全局布局。

- 资产相对损益=`持仓毛损益-期初持仓价值×基准毛收益`；现金项=`实际现金利息-期初现金×基准毛收益`；既有账户差延续=`(期初策略价值-期初基准价值)×基准毛收益`。年费/交易费项各为基准费用减策略费用。它们相加等于当日策略与基准终值差的变动，逐日直接求和闭合到最终账户金额差，不使用行业单位资本的跨期收益链接权重。
- 新投入只在收盘后进入持仓，不赚取投入前的行情和利息；投入不计损益。基金净值已含日常费用，不再次扣管理费；基准同流毛指数。宽基基准仍使用同佣金/滑点/年费，三档基准为同流毛指数，成本口径不自动统一。
- 因子/股票/基金相对项是事后账本效果，不是因果择时、真实Alpha或Smart Beta。`alphaReturn/smartBetaReturn/residualReturn`为空。月度金额不是月收益率，贡献不能与TWR或XIRR相加；C现金仍是模型利率，不是债券真实业绩。
- 闭合容差依据参与运算金额ULP与项目数计算，逐日和全期保留`error/errorBound`，大额近零超额不误拒绝，错误账本仍拒绝。允许合计误差1e-8内的配置权重先规范化，实际权重保存在结果数据口径，原用户配置不改写。三档换手成本固定代码顺序稳定求和；宽基主源码改为捕获字节执行与SHA绑定。

## 行业收益归因首批

仅用于新执行的原始行业与自建行业单位资本结果，旧结果不改写。`industry_engine.py`在实际账本记录期初股票比例、每日年费与交易费，执行后计算并保存`attribution`，前台结果详情显示全期分项、闭合误差、月度筛选、单基准回归与最近30日审计。既有交易/费用算法和净值不改变。

- 当日现金暴露机会成本=`(期初股票比例-1)*基准收益`；行业相对选择=`持仓毛收益-期初股票比例*基准收益`；年费/交易成本分别为负的实际账本金额除以期初净值。四项和等于当日净策略减基准收益；初始收盘买入不赚取当日价格涨幅，但计初次交易成本。
- 不能直接把每日算术超额相加当全期收益。终值链接权重=`前日策略净值*期末基准净值/当日基准净值`，加权贡献和严格闭合到期末策略净值减基准净值（期初资本1）。这是非年化终值收益差，不是年化收益差或IRR。月度贡献使用同一全期链接权重，只能相加到全期终值差，不是每月收益率。
- 链接权重包含后续基准变化，只用于已完成回测的事后解释，不进入因子评分或交易信号。每日原始分项不依赖后续数据，月度链接贡献可能随终点改变。
- OLS：`策略净收益=每观测截距+Beta*基准收益+残差`，无风险收益假设0，包含初次成本日。至少3观测且基准有足够变化才计算；恒定基准/短样本不可识别。相对市场项为`(Beta-1)*基准收益`，样本截距与残差的链接贡献也闭合到终值超额。不提供年化截距、显著性或样本外保证。
- 现金暴露不是因果择时，行业相对选择不等于因子Alpha。`alphaReturn/smartBetaReturn/residualReturn`旧语义字段保留空值；回归残差在独立诊断项中展示。缺少独立因子收益与风险模型，不能声称已拆出多因子Smart Beta；三档/定投现金流归因未覆盖。指数/股息近似、披露时点与幸存者偏差限制继续保留。

数值或账本不闭合时拒绝生成结果，不通过伪造一个“残差桶”掩盖错误。归因版本`industry-terminal-link-v1`与执行源码指纹随结果保存。

`/api/modules/factors/v1/data-quality`提供回测前数据质量与口径审计，读取旧导出的coverage、repair、turnover日志和当前schema探针，展示原始失败、修复后状态、字段可读性、换手成本敏感度和执行边界。

已覆盖：

- 数据资产：基金宽表、基金SQLite、月度更新脚本、离线宽表生成脚本、ETF行业面板、宽基面板和基准面板。
- 更新任务：登记月度/季度更新入口、工作目录、输入输出、联网边界和当前状态。
- 历史导出：登记旧`etf-smartbeta/out`中的结果文件，标记哪些已被原生视觉实验台使用，哪些待后续迁移。
- Schema探针：CSV只读取文件开头识别字段；SQLite只读读取表/视图结构和字段定义；parquet只读metadata/footer识别字段、行数和row group；`panel.json`读取结构键和因子字段。

- 数据质量审计：区分原始采集失败和修复后状态，登记Schema可读性、换手风险、成本敏感度和回测前检查项。

边界：打开页面只读取元数据和schema；历史样本查询按下述范围读取，基金分组与执行筛选按专节只读扫描全表，不触发`07_update.sh`。

### 历史数据查询

`GET /api/modules/factors/v1/data-layer/preview`支持已登记的基金CSV、行业panel、宽基broad和基准bench。参数为`assetId`、重复的`field`、`q`、`dateField`、`startDate`、`endDate`、`limit`、`offset`和可选的`sourceVersion`。不接受任意文件路径。

- 每次选择1至12个字段、返回1至50行，最多检查当前位置之后5000行；下一批沿用原筛选条件。
- 日期筛选是闭区间；关键词仅匹配所选字段；CSV原始代码保留前导零。
- 字段字典显示全部字段和Parquet字段类型；CSV未强行推断类型。
- 样本显示缺失值计数、已扫描范围、是否到达文件末尾及snapshot候选；这些计数不代表全表数据质量或全量筛选结果。
- 文件大小与mtime作为当前版本指纹。翻页前后若版本变化返回409，要求重新查询；它不是内容哈希，也不等同于冻结snapshot。
- Python使用标准CSV解析器，Parquet查询需要`pyarrow`。失败返回可识别错误，不回落到旧导出曲线。

验证通过31项Node测试（其中包含5个隔离CSV/Parquet读取测试）；2026-10-01本地预览启动被`listen EPERM`阻断，新增页面交互的浏览器验收待补。完整剩余清单见[迁移清单](../../docs/wiki/FACTOR-MIGRATION.md)。

## 常用因子库

`/api/modules/factors/v1/library`已登记并扩充常用因子库：12个因子族、64个字段。这个库是开放式入口，后续可以持续补充自研、论文和业界常用因子。

行业/ETF线：

- 行业价值：BM、EP、PB/PE历史分位反向和价值综合分。
- 行业动量：12-1、6-1、3月、1月动量和动量综合分。
- 行业景气与质量：盈利同比、环比、加速度、BPS增长和景气综合分。
- 行业拥挤与风险：换手、成交额占比、估值扩张、动量二阶、60日波动和拥挤综合分。
- 行业低波与防御：短中期波动、下行波动、Beta和滚动回撤。
- 行业红利：股息率、股息率分位、股息稳定性和红利价值组合。
- 行业规模与流动性：成交额占比、换手率、分位和ETF可投资容量。

基金宽表线：

- 基金绝对收益与风险：年化收益、区间收益、最大回撤、夏普、索提诺、卡玛、月度胜率。
- 基金基准相对：超额年化、跟踪误差、信息比率、月度超额胜率、上/下行捕获。
- 基金持仓结构与漂移：股票仓位、行业HHI、前十大集中度、第一大行业、平均/最大风格漂移。
- 基金费用与成本：管理费、托管费、销售服务费、综合费率和费用后信息比率。
- 基金经理与产品结构：经理任职、在管产品数、在管规模、产品年限和主份额标记。

因子库现在支持查询、复制、提交和修改。内置库保留在代码合约中，页面提交的新定义写入`var/factors/library-submissions.json`；`/api/modules/factors/v1/library`会合并内置库和本地提交库返回。提交表单要求写清楚计算逻辑、使用逻辑、子因子/指标定义、字段公式、方向、缺失值策略和注释。当前仍不计算因子值。

可维护入口：

- 查询：`GET /api/modules/factors/v1/library`
- 查看本地提交：`GET /api/modules/factors/v1/library/submissions`
- 新增提交：`POST /api/modules/factors/v1/library/submissions`
- 修改提交：`PUT /api/modules/factors/v1/library/submissions/{factorFamilyId}`

## 回测执行准备区

`/api/modules/factors/v1/backtest-engine`、`/api/modules/factors/v1/execution-plan`、`/api/modules/factors/v1/run-requests`和`/api/modules/factors/v1/result-artifacts`已接入执行与结果资产层。该层用于把已保存的策略配置交给本地执行器或后续回测Skill。

`/api/modules/factors/v1/experiment-comparison`已把旧`lab_comps.json`中的A/B/C实验组合对比迁成原生只读接口，计算每条序列的终值、年化、最大回撤、相对基线差异和有效起点。前端展示组合净值对比、方案排名和B组因子权重方案。

已覆盖：

- 引擎状态：展示当前`panel.json`月度横截面TopN和`broad.parquet`固定宽基定投执行器、仅供历史查询的旧导出资产、后续行业Parquet/基金宽表引擎与审计清单。
- 执行阶段：绑定配置、校验snapshot、解析因子、选择执行器、生成结果资产、登记结果产物。
- 配置就绪检查：检查`snapshotId`、`factorFamilyIds`、`benchmarkId`、`costModel`、`rebalanceCalendar`和结构化策略参数。
- 执行器候选：从旧artifact候选中筛出回测引擎、因子研究和敏感度网格。
- 运行请求记录：可保存`run.*`请求，写入`var/factors/run-requests.json`。
- 本地V1执行：`POST /api/modules/factors/v1/run-requests/{requestId}/execute`会读取同一个`configId`。行业面板配置优先读取旧导出的`panel.json`，按配置因子权重逐月打分、选择TopN、扣除换手成本和费率，生成标准结果资产并写入`var/factors/result-artifacts.json`。
- 配置不支持时：返回422；旧导出资产保持历史只读，新请求不自动封装旧曲线。
- 结果资产库：`/api/modules/factors/v1/result-artifacts`记录指标、账户曲线、单位净值、Alpha/Smart Beta/残差归因、因子诊断、敏感度、警示和数据口径；`/api/modules/factors/v1/result-artifacts/{artifactId}`提供单条详情和复核清单。前端执行区可选择结果资产并展开指标、持仓、归因、敏感度和警示详情。

边界：执行器不联网、不抓取、不调用旧脚本；旧行业读取panel.json，新增原始行业策略读取三文件数据包，固定宽基读取broad.parquet，三档读取八文件数据包，基金筛选读取wide_today.csv，手动基金篮子历史定投只读新工作台SQLite。全部沿用同一请求/结果接口；历史因子选基和完整归因仍待完成。
